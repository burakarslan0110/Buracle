# Contributing

Buracle is one developer's harness, published as it is. Bug reports, questions and small, focused
pull requests are welcome. For a larger change, open an issue first so the change is agreed before
the work starts.

## Set up

- Bun at the version in `.bun-version` (`engines.bun` in `package.json` names the minimum).
- `bun install` installs the exact-pinned dependencies from `bun.lock`.
- The CLI runs from source: `bun src/cli/main.ts --help`. Every run refreshes
  `$BURACLE_HOME/state/runtime-config.json`, which the installed harnesses read, so point `HOME`
  and `BURACLE_HOME` at a temp folder while developing:
  `T=$(mktemp -d) && HOME=$T BURACLE_HOME=$T/.buracle bun src/cli/main.ts build`.

## Where to change things

- `canonical/` is the single source of the skills, rules, agents and the YAML data; `src/` is the
  code.
- `harness/` is generated by `buracle build` and committed; never edit it by hand. Change
  `canonical/` or `src/`, run the sandboxed build above and commit its output with the change.
  The build also writes `docs/reference/`, which stays out of git like the rest of `docs/`.
- `src/core/` stays pure: relative imports only, no `node:*`, `bun:*`, `process`, timers or
  randomness. `tests/core/purity.test.ts` enforces it.
- Dependencies: add none. `AGENTS.md` lists the runtime and dev dependencies.
- Everything is written in English (code, comments, docs, agent texts);
  `tests/workflow/language-guard.test.ts` enforces it.

[`AGENTS.md`](AGENTS.md) holds the full rules of the repository.

## Before you open a pull request

Work on the `dev` branch: `main` holds only released files, without the test suite. Run the three
release checks. GitHub Actions runs the same three on every push to a branch other than `main`.

```sh
bunx tsc --noEmit -p .
T=$(mktemp -d) && HOME=$T BURACLE_HOME=$T/.buracle bun src/cli/main.ts build --check
bun test
```

- Tests live in `tests/` and mirror `src/`. Anything that touches the filesystem uses
  `withSandbox()` from `tests/helpers/sandbox.ts`. Tests never touch the real `~/.claude`,
  `~/.codex`, `~/.config/opencode`, `~/.omp`, `~/.agents` or `~/.buracle`;
  `tests/zz-real-home-untouched.test.ts` checks that after the run.
- Memory tests run against the fake CortexDB in `tests/fixtures/cortexdb/`; never download or run
  the real binary in a test.
- After a Bun upgrade, `build --check` fails until the OpenCode and omp bundles are rebuilt and
  committed. Update `.bun-version` in the same commit.

Keep a pull request to one change, say what you verified and how, and update the documentation
that describes the behavior you changed (`README.md`, `README.tr.md`, `AGENTS.md`).

## Releases

Work lands on `dev`. When CI passes there on every platform and the released files changed, CI
picks the next patch version by itself, writes the commit to `main` at that version and without the
test suite (`tests/` and `bunfig.toml`), one commit per release, and publishes `v<version>` from it
with both install scripts attached. To start a new line, raise the major or minor version in
`package.json`. The install scripts clone `main`, and `buracle update` follows it, so users get
exactly the released files. CI never runs on `main`.
