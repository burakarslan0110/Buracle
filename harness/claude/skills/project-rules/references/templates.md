# Templates and writing rules

Replace every `<…>` with a verified value and delete sections that would stay empty. Never leave
a placeholder, `TODO`, `TBD` or `FIXME` in a written file.

## Root `AGENTS.md`

````markdown
# <Project name>

<One or two sentences: what this repository is, its main language and framework.>

## Commands

| Task | Command |
|---|---|
| Install | `<cmd>` |
| Build | `<cmd>` |
| Typecheck | `<cmd>` |
| Lint / format | `<cmd>` / `<cmd>` |
| All tests | `<cmd>` |
| One test file | `<cmd> <path>` |

<Prerequisites in one line each, e.g. "Integration tests need the database: `docker compose up -d db`.">

## Layout

- `<dir>/` — <what lives here; only when the name does not say it>
- `<dir>/` — generated by `<cmd>`; never edit by hand.

## Conventions

- <Imperative rule that differs from the ecosystem default> — <reason, if not obvious>.

## Testing

- <Where tests go, naming, fixtures, and what every change must include.>

## Gotchas

- <Verified trap>: <symptom> → <what to do>.

## Scoped rules

Read the matching rule before editing those files.

- `.claude/rules/<slug>.md` — `<glob>` — <purpose>

## Project tools

- `<server or CLI>` — <what it is for>; consult it when <situation>.
````

Writing rules:

- One instruction per bullet, imperative mood, exact names in backticks.
- Give the reason when it is not obvious; a reason lets agents handle the cases the rule misses.
- Prefer "do X" over "don't do Y"; when you must forbid, name the alternative.
- No harness tool names, no emojis, no dates, no counts that change.
- Commands must be copy-pasteable from the repo root (or say which directory).

## Path rule: `.claude/rules/<slug>.md`

```markdown
---
paths: ["<glob>", "<glob>"]
---
Applies to <which files, in plain words>.
- <Imperative rule> — <reason>.
- <Imperative rule>.
- Check with `<cmd>`.
```

- `paths` is the only frontmatter field Claude Code reads. Quote every glob; brace expansion works
  (`"src/**/*.{ts,tsx}"`).
- Name the file after its topic in kebab case: `sql-migrations.md`, `react-components.md`.
- A rule without `paths` loads in every Claude Code session and in no other harness. Put such
  content in `AGENTS.md` instead.

## Nested `<subdir>/AGENTS.md`

```markdown
# <Package name>

<One line: what this package is and how it relates to the rest.>

## Commands (run from `<subdir>/`)

| Task | Command |
|---|---|
| Tests | `<cmd>` |

## Rules

- <Only what differs from the root AGENTS.md.>
```

Codex concatenates `AGENTS.md` files from the repo root down to the working directory, and the
other harnesses load nested files when they work in that directory. Never repeat root content.

## Existing `CLAUDE.md`

```markdown
@AGENTS.md

- <Claude Code note, if any; otherwise nothing else in this file>
```

Codex, OpenCode and omp read the `AGENTS.md` in the same folder instead, so a note here reaches
Claude Code alone. Personal notes go into the gitignored `CLAUDE.local.md`. When `CLAUDE.md` is a
symlink to `AGENTS.md`, keep the link and do not write to it. A `.claude/CLAUDE.md` starts with
`@../AGENTS.md` instead: Claude Code and omp both read it in place of the root `AGENTS.md`.

## Project tools entry

Only for servers or CLIs specific to this repository: a project `.mcp.json` (Claude Code),
`.codex/config.toml` `[mcp_servers.*]` (Codex, trusted projects only), `opencode.json(c)` `mcp`
(OpenCode), or a repo script that answers questions; omp reads all three server files. Smoke-test
one read-only call first and keep the result for the report: whether a server is up changes, so
it never goes into `AGENTS.md`. Then:

```markdown
- `billing-db` MCP (read-only replica) — table schemas and row counts; consult it before writing
  queries or migrations.
```

In the report, list each server with the harnesses whose config declares it and the ones that
cannot reach it. Adding a declaration to another harness's config makes a second copy to keep in
step, so offer it and let the user decide.

Buracle's own servers (`context7`, `codegraph`, `semble`, `web-search`, `web-fetch`, `grep`,
`chrome-devtools`, `buracle-memory`, `context-mode`) are covered by Buracle's routing card in every
harness; do not repeat them here.
